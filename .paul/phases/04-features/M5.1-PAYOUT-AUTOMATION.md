# M5.1 — Payout Automation (SRI Integration)

**Estado:** 📋 PLANIFICADO
**Prioridad:** P0 (crítico para modelo de negocio)
**Dependencias:** M3 Payments Gateway (Commission model exists)

---

## 🎯 Problema

Actualmente las comisiones (`Commission` model) se generan automáticamente al concretar una venta, pero **no se pagan** — están en estado `PENDING` indefinidamente. Los vendedores deben recibir transferencias bancarias automáticas a sus cuentas.

## ✅ Solución

Automatizar el flujo:
1. **Comisión generada** → `Commission.status = PENDING`
2. **Batch diario** (Celery Beat) reúne comisiones `PENDING` por vendedor
3. **Crea `Payout`** por vendedor (agrupado) con `BankAccount` predeterminada
4. **Envía a SRI** (o banco) vía webservice SOAP con certificado digital
5. **Webhook SRI** confirma transferencia → `Payout.status = PAID` + `Commission.paid_at`
6. **Notifica** al vendedor (email/Telegram) con referencia de transferencia

```python
from celery import shared_task, Task
from django.core.mail import send_mail
from .models import Payout, Commission, BankAccount
from .integrations.sri import SRIClient

@app.task(bind=True, queue='payments', max_retries=3)
def process_payout_batch(self, payout_ids: list[uuid.UUID]):
    """Procesa batch de payouts (uno por commission)."""
    failed = []
    for payout_id in payout_ids:
        try:
            payout = Payout.objects.select_related('bank_account', 'commission').get(id=payout_id)
            if payout.status != PayoutStatus.PENDING:
                continue

            # Obtener cliente SRI (cargar cert desde settings)
            client = SRIClient(
                cert_path=settings.SRI_CERT_PATH,
                cert_password=settings.SRI_CERT_PASSWORD,
                environment=settings.SRI_ENVIRONMENT
            )

            # Enviar transferencia
            result = client.create_transfer(
                bank_account=payout.bank_account,
                amount=payout.amount,
                reference=str(payout.id)
            )

            if result['success']:
                payout.status = PayoutStatus.PROCESSING
                payout.provider_response = result
                payout.save()
            else:
                payout.status = PayoutStatus.FAILED
                payout.error_message = result.get('error', 'Unknown error')
                payout.save()
                failed.append(str(payout_id))

        except Exception as exc:
            self.retry(exc=exc, countdown=60)

    if failed:
        send_payout_batch_failed_email(failed)
```

### 5. Webhook SRI/Banco

```python
# apps/core_payments/api/views.py
class SRIPayoutWebhookView(APIView):
    """
    Webhook endpoint para confirmación de transferencias SRI/Banco.
    Header: X-SRI-Signature (firma HMAC)
    Body: { "transaction_id": "...", "status": "PAID", "timestamp": "..." }
    """
    permission_classes = [AllowAny]  # verified via signature

    def post(self, request):
        signature = request.headers.get('X-SRI-Signature')
        payload = request.data

        # Verificar firma HMAC
        expected = hmac.new(
            settings.SRI_WEBHOOK_SECRET.encode(),
            request.body,
            hashlib.sha256
        ).hexdigest()
        if not hmac.compare_digest(signature, expected):
            return Response({'error': 'Invalid signature'}, status=403)

        # Buscar payout por transaction_id en provider_response
        payout = Payout.objects.filter(
            provider_response__transaction_id=payload['transaction_id']
        ).first()

        if not payout:
            return Response({'error': 'Payout not found'}, status=404)

        if payload['status'] == 'PAID':
            payout.status = PayoutStatus.PAID
            payout.paid_at = payload['timestamp']
            payout.save()
            payout.commission.status = CommissionStatus.PAID
            payout.commission.paid_at = payload['timestamp']
            payout.commission.save()
            send_payout_confirmed_email(payout)

        return Response({'status': 'ok'})
```

## 🔐 Security Considerations

- Bank account numbers encrypted at rest (`django-encrypted-model-fields`)
- Payout modifications solo por owner o admin
- Webhook signature verification (HMAC-SHA256)
- Rate limiting en payout creation (max 1000/day por usuario)
- Audit log: `PayoutAuditLog` model (who created/confirmed/cancelled)
